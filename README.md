# RAG по Трудовому кодексу РФ

Вопрос на русском, гибридный поиск по 534 статьям ТК РФ в редакции от 25.05.2026, затем ответ Claude Haiku 4.5. Модель отвечает только по найденным статьям и ставит цитату `[ст. N]` у каждого утверждения. Расходы на модель ограничены жёстким дневным лимитом, счётчик виден на странице.

**Коротко**

- Поиск: гибрид BM25 и `multilingual-e5-small` (int8 ONNX), слияние через RRF. Hit@5 — 81,4% на 43 вопросах, на отложенной части (test) — 81,0%. Прогон 2026-10-05, файл [`evals/latest.md`](evals/latest.md).
- Качество ответов модели (точность цитат, отказы, стоимость ответа) не прогонялось: нужен ключ API.
- Cost guard: $1.00 в сутки, 10 вопросов в час с одного IP, `max_tokens` 600, вопрос обрезается до 500 символов. При превышении — вежливый отказ.
- Настройки поиска подбирались только на dev-части вопросов, test в подборе не участвовал. Протокол и все итерации с цифрами — в [`evals/tuning.md`](evals/tuning.md).
- Docker-контейнер занимает 288–312 МиБ памяти при лимите 700 МиБ. Слушает только localhost.

## Задача

Сотрудник или кадровик спрашивает разговорным языком: «Женюсь в следующем месяце, сколько дней за свой счёт мне обязаны дать?». Системе нужно:

1. найти нужную статью среди 534, хотя в вопросе нет ни одного слова из её текста;
2. ответить только по тексту статьи и показать, откуда взят ответ;
3. честно сказать «в базе нет ответа», если вопрос не про кодекс (ставка НДФЛ, ипотека);
4. не дать публичной странице потратить на модель больше заданной суммы.

## Решение

- **Корпус.** ТК РФ в редакции от 25.05.2026, постатейно с consultant.ru. Сверен с официальным текстом pravo.gov.ru: у 519 из 532 общих статей совпадение пословно не ниже 0,97, остальные расхождения разобраны вручную в [`data/SOURCE.md`](data/SOURCE.md).
- **Фрагменты.** Статья режется на части до 350 символов. Каждая часть несёт заголовок «Статья N. Название (часть i из n)», поэтому одиночный фрагмент всегда говорит, откуда он. Всего 3200 фрагментов.
- **Поиск.** BM25 со стеммингом Snowball для русского языка и dense-поиск на e5-small, слияние Reciprocal Rank Fusion с весами 1 : 1,5. Векторной БД нет: numpy и JSON, полный перебор матрицы 3200 × 384.
- **Эмбеддинги без тяжёлых зависимостей.** Свой раннер на onnxruntime и SentencePiece вместо fastembed и HF `tokenizers`. Только JSON-токенайзер HF занимал в памяти +386 МБ, а файл SentencePiece весит 5 МБ. Эмбеддинги совпадают со стандартной реализацией: косинус не ниже 0,9992. Замеры — в [`docs/design.md`](docs/design.md).
- **Ответ.** `claude-haiku-4-5-20251001`, `temperature=0`. Модель получает только найденные фрагменты. Если ответа в них нет, она отвечает «В базе нет ответа на этот вопрос.». Цитаты в интерфейсе — ссылки на фрагменты.
- **Без ключа.** Демо-режим: поиск настоящий, вместо ответа модели показаны найденные фрагменты с пометкой «демо-режим без ключа».

## Архитектура

```
 браузер ── POST /api/ask ──► FastAPI, один процесс uvicorn
                                  │
                  вопрос обрезается до 500 символов
                                  │
                  cost guard (SQLite) ── лимит в час на IP ─────► 429
                                  │      резерв худшей стоимости ──► отказ «бюджет на сегодня исчерпан»
                                  ▼
              ┌──────────────── поиск ────────────────┐
              │ BM25, стемминг         e5-small int8  │
              │ top-30 фрагментов      top-30 (косинус)│
              └────────── RRF, веса 1 : 1,5 ──────────┘
                                  │ top-5 фрагментов
                                  ▼
              Claude Haiku 4.5 (без ключа — заглушка)
              <fragments>…</fragments>  <user_question>…</user_question>
                                  │ usage из ответа → фактический расход в SQLite
                                  ▼
              ответ с [ст. N] → ссылки на фрагменты; фрагменты со score

 офлайн:
   data/corpus.jsonl ─► app.build_index ─► var/index/ (meta.json, chunks.json, embeddings.npy)
   data/evals.jsonl  ─► app.evals ─► evals/latest.{json,md} ─► страница /evals
```

## Метрики

Прогон 2026-10-05 на сервере демо (Linux x86_64, Python 3.12, onnxruntime 1.30.0), файлы [`evals/latest.md`](evals/latest.md) и `evals/results-2026-10-05.json`. Набор — 50 вопросов: 34 с ответом в одной статье, 9 с ответом в двух статьях и 7 без ответа в кодексе. Вопросы без ответа в hit@k не входят. Статья засчитывается по лучшему из своих фрагментов.

| Поиск, 43 вопроса | hit@1 | hit@3 | hit@5 | MRR@10 |
|---|---|---|---|---|
| BM25 | 32,6% | 51,2% | 58,1% | 0,425 |
| Dense (e5-small) | 69,8% | 86,0% | 90,7% | 0,766 |
| **Гибрид, работает в демо** | 55,8% | 79,1% | 81,4% | 0,673 |

| Гибрид по частям набора | n | hit@1 | hit@3 | hit@5 | MRR@10 |
|---|---|---|---|---|---|
| dev (на нём подбирались настройки) | 22 | 40,9% | 77,3% | 81,8% | 0,575 |
| test (отложен) | 21 | 71,4% | 81,0% | 81,0% | 0,775 |

**Ответы модели: не прогонялось, нужен ключ.** Точность цитат, корректные отказы на вопросах без ответа, стоимость и латентность ответа не измерены. Код для этого готов: `python3 -m app.evals --answers`.

Что стоит знать о цифрах:

- **Подбор.** Три итерации на dev: фрагменты 1200 → 350 символов, в индекс идёт заголовок без названия главы, веса RRF 1 : 1,5. На сервере на test hit@5 не изменился (81,0% → 81,0%), hit@1 вырос с 57,1% до 71,4%, MRR — с 0,677 до 0,775. На всём наборе hit@5 вырос с 72,1% до 81,4%, но в эту цифру входит dev, на котором шёл подбор.
- **Цель не достигнута.** Для гибрида целью был hit@5 ≥ 85%, получилось 81,4%. На этом сервере dense без BM25 даёт больше (90,7%). Переключаться на него по тем же вопросам, по которым он измерен, значит подгонять под тест. Решать надо на новом отложенном наборе. BM25 пока остаётся ради запросов с номерами статей: на «статья 186.1» dense ставит нужную статью седьмой, гибрид — первой.
- **Платформа влияет на цифры.** Модель квантована в int8, и на разных CPU эмбеддинги немного различаются. На Mac (arm64) тот же набор даёт гибрид 83,7%, dense 86,0% (`evals/results-2026-10-05-darwin-arm64.json`). Поэтому в каждом отчёте записана платформа.
- **Набор маленький.** 43 вопроса: один вопрос — это 2,3 п. п. Вопросы составлены для этого проекта, независимой разметки не было. Каждая ожидаемая статья проверена чтением, а в формулировках нет пяти подряд слов из её текста ([`data/README.md`](data/README.md)).

## Cost guard

- **Дневной лимит.** `DAILY_BUDGET_USD`, по умолчанию $1.00, сутки по UTC, учёт в SQLite. Перед вызовом модели резервируется худшая стоимость: 5 фрагментов максимальной длины, вопрос, системный промпт и полные 600 токенов ответа по ценам Haiku 4.5 ($1 за 1M входных и $5 за 1M выходных токенов). Сейчас это до $0.0074 на вопрос. Проверка и резерв идут в одной транзакции, поэтому параллельные запросы не проскочат лимит вместе. После ответа резерв заменяется фактом из `usage`.
- **Ошибки API.** Если API вернул ошибку, резерв снимается. При таймауте резерв остаётся: запрос мог быть обработан.
- **Rate limit.** 10 вопросов в час с одного IP, скользящее окно. IP хранится только как HMAC и только час. `X-Forwarded-For` учитывается только от адресов из `TRUSTED_PROXY`.
- **Ограничения размера.** `max_tokens` 600. Вопрос длиннее 500 символов обрезается, длиннее 5000 — отклоняется.
- **Исчерпан лимит.** Пользователь получает вежливый отказ и всё равно видит найденные фрагменты. На странице показано «потрачено сегодня $X из $Y».

Фактическая стоимость ответа не измерена: нужен ключ.

## Защита от prompt injection

- Фрагменты лежат в `<fragments>`, вопрос — в `<user_question>`. Вопрос HTML-экранируется, поэтому закрыть тег или подделать фрагмент из вопроса нельзя.
- Системный промпт прямо говорит, что содержимое `<user_question>` — данные, а не инструкции.
- Ответ модели экранируется на сервере, и только потом `[ст. N]` превращаются в ссылки. Цитата на статью, которой нет среди найденных фрагментов, выводится зачёркнутой красной пометкой: выдуманная ссылка видна сразу.
- Страница не грузит внешних ресурсов. CSP: `script-src 'self'`, `frame-ancestors 'none'`.

Экранирование и разбор цитат покрыты тестами. Атаки на живую модель не прогонялись: нужен ключ.

## Ограничения

- Это не юридическая консультация. Корпус взят из справочной системы, а не из официального опубликования, редакция от 25.05.2026. Более поздние поправки не учтены.
- Качество ответов модели не измерено.
- Фрагменты короткие: 5 штук по 350 символов — это около 1,7 тыс. символов контекста. Для вопросов на две статьи этого может не хватить. Проверить можно только прогоном `--answers`.
- Один процесс uvicorn и SQLite: демо рассчитано на небольшой поток.
- Контейнер слушает только `127.0.0.1`. Для публичного доступа нужен обратный прокси с TLS и `TRUSTED_PROXY`.

## Что дальше

1. Прогнать `--answers` с ключом (лимит на прогон `--max-usd 0.50`) и опубликовать точность цитат, отказы, стоимость и латентность.
2. Расширить набор до 150–200 вопросов с независимой разметкой и новой отложенной частью. На ней решить, оставлять ли BM25 и с каким весом.
3. По ответам модели выбрать TOP_K: 5 или 8 фрагментов.
4. Замерить память с реранкером (cross-encoder): помещается ли он в лимит 700 МиБ.

## Запуск локально

Нужен Python 3.12.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python3 -m pytest                                          # 87 тестов, без сети и без ключа
python3 -m app.build_index --corpus data/corpus.jsonl      # при первом запуске скачает модель (~125 МБ)
uvicorn --factory app.main:create_app --port 8000 --no-proxy-headers
```

Без `ANTHROPIC_API_KEY` приложение работает в демо-режиме. Чтобы включить ответы модели, задайте ключ перед запуском: `export ANTHROPIC_API_KEY=...`.

Evals:

```bash
python3 -m app.evals --evals data/evals.jsonl              # только поиск, без LLM
python3 -m app.evals --evals data/evals.jsonl --split dev  # только dev-часть, для подбора настроек
python3 -m app.evals --evals data/evals.jsonl --answers    # плюс ответы модели, нужен ключ, лимит --max-usd 0.50
```

## Docker

```bash
cp .env.example .env               # необязательно; ключ — в ANTHROPIC_API_KEY
docker compose -p demo-rag up -d --build
curl -s 127.0.0.1:18101/api/health
curl -s -X POST 127.0.0.1:18101/api/ask -H 'Content-Type: application/json' \
     -d '{"question": "Сколько длится испытательный срок?"}'
```

Как устроен контейнер:

- образ `python:3.12-slim`, процесс работает от непривилегированного пользователя, `cap_drop: ALL`, `mem_limit: 700m`;
- индекс, кеш модели и SQLite с учётом расходов лежат в volume;
- индекс строится при первом старте и пересобирается, когда меняется корпус или версия индекса. На 2 vCPU это около 2,5 минуты вместе со скачиванием модели;
- порт — только `127.0.0.1:18101`.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | без ключа — демо-режим |
| `DAILY_BUDGET_USD` | `1.00` | дневной лимит расходов на модель, сутки по UTC |
| `RATE_LIMIT_PER_HOUR` | `10` | вопросов в час с одного IP |
| `MAX_TOKENS` | `600` | предел длины ответа |
| `MAX_QUESTION_CHARS` | `500` | более длинный вопрос обрезается |
| `TOP_K` | `5` | сколько фрагментов уходит в модель |
| `CHUNK_MAX_CHARS` | `350` | размер фрагмента (подобран на dev) |
| `BM25_WEIGHT` / `DENSE_WEIGHT` | `1.0` / `1.5` | веса RRF (подобраны на dev) |
| `TRUSTED_PROXY` | пусто | IP или CIDR прокси, которым можно верить в `X-Forwarded-For` |

Полный список — в `.env.example` и `app/config.py`.
