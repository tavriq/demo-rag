# data/: корпус и eval-набор

| Файл | Что внутри |
|---|---|
| `corpus.jsonl` | Трудовой кодекс РФ, ред. от 25.05.2026: 534 статьи, одна строка — одна статья |
| `evals.jsonl` | 50 вопросов для проверки поиска и ответов |
| `build_corpus.py` | Сборщик корпуса, только стандартная библиотека Python |
| `SOURCE.md` | Откуда взят текст, почему этот источник и как сверяли с официальным |

## corpus.jsonl

```json
{"id": "TK-99", "article": "99", "title": "Сверхурочная работа",
 "chapter": "Глава 15. Общие положения", "section": "Раздел IV. Рабочее время",
 "text": "1. Сверхурочная работа - ...\n2. Привлечение ... в следующих случаях:\n1) ...\n2) ...",
 "source_url": "https://www.consultant.ru/document/cons_doc_LAW_34683/...", "edition_date": "2026-05-25"}
```

- `id` имеет вид `TK-<номер статьи>`. Номера с точкой и дефисом тоже бывают: `TK-22.1`, `TK-84.1`, `TK-341.1-1`.
- `title` — название статьи без слов «Статья N.».
- `chapter` — номер и название главы. `section` — раздел кодекса. Это дополнительное поле: у многих глав название «Общие положения», и без раздела непонятно, о чём глава.
- `text` — полный текст статьи:
  - Части пронумерованы по порядку: `1. `, `2. ` и т. д.
  - Пункты (`1)`, `а)`) и абзацы перечней идут отдельными строками внутри своей части.
  - Утратившие силу части оставлены на месте («6. Часть шестая утратила силу. - …»), поэтому номер части в корпусе совпадает с официальным: «ч. 6 ст. 99» — это строка `6. ` в тексте ст. 99. Если одной пометкой утрачены сразу несколько частей, она получает диапазон: «3-4. Части третья - четвертая утратили силу».
  - Примечания к статье, если они есть, идут в конце.
- `edition_date` — дата редакции, одна на весь корпус.

Немного статистики: в среднем 1 516 символов на статью, медиана 998, самая длинная — TK-422 (11 853 символа). Длинные статьи перед индексацией нужно резать на фрагменты.

Пересборка (сеть, около часа: страницы качаются по одной с паузами):

```bash
python3 data/build_corpus.py --cache /tmp/tk-cache --out data/corpus.jsonl
python3 data/build_corpus.py --cache /tmp/tk-cache --offline   # только разбор уже скачанного
```

## evals.jsonl

```json
{"q": "Хочу уволиться по собственному. За сколько надо предупредить начальство?",
 "expected_ids": ["TK-80"], "answer_hint": "Письменно не позднее чем за две недели ...", "type": "factual"}
```

| type | Сколько | Что проверяет |
|---|---|---|
| `factual` | 34 | ответ есть в одной статье |
| `multi_hop` | 9 | для полного ответа нужны две статьи, обе в `expected_ids` |
| `negative` | 7 | ответа в кодексе нет (ставка НДФЛ, размер МРОТ в рублях, процент больничного, штрафы по КоАП, цена патента, ипотека, налоговый вычет); `expected_ids` пустой, правильное поведение — отказ |

Как составляли:

- Вопросы написаны разговорным языком сотрудника или кадровика. Скрипт проверил, что ни в одном вопросе нет пяти подряд слов из текста ожидаемой статьи.
- Каждый `expected_id` проверен чтением статьи. Дополнительно скрипт убедился, что ключевая фраза ответа (например, «не позднее чем за две недели») стоит именно в тексте этой статьи корпуса.
- Для negative скрипт регулярными выражениями поискал по всему корпусу ставки налога, суммы МРОТ и штрафов, слова «ипотека», «налоговый вычет», стоимость патента. Совпадений нет.
- `answer_hint` — одна фраза с сутью ответа, а не эталонный текст.
- Один вопрос (сверхурочные) опирается на поправку 2026 года: лимит «4 часа в день, до 240 часов в год по коллективному договору». Он проверяет, что ответ взят из актуальной редакции.

## Ограничения

- Источник — справочная правовая система, а не официальное опубликование (подробности в `SOURCE.md`). Поправки после 25.05.2026 и изменения, не вступившие в силу на дату сбора, не учтены.
- Номера частей проставлены эвристикой: абзац с заглавной буквы начинает новую часть. Её проверили двумя способами:
  - по 222 редакционным пометкам вида «(часть шестая в ред. …)» — расхождений 0;
  - по 23 пометкам «Часть N утратила силу»: номер строки совпал с номером в пометке во всех случаях. Ещё 3 совместные пометки («Части … утратили силу») получили диапазоны номеров.

  В статьях без таких пометок ошибка нумерации остаётся возможной.
- `expected_ids` перечисляют основную статью или статьи. По некоторым вопросам что-то полезное есть и в соседних статьях: например, к вопросу о замене отпуска деньгами (ст. 126) относится и ст. 127 о компенсации при увольнении. Recall по этому набору — оценка снизу.
- Вопросы составил один автор, без независимой разметки.
- В `data/` метрик нет: здесь только входные данные. Метрики поиска и ответов считает отдельный прогон.
